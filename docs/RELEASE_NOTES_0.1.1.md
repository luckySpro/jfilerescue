## JFileRescue 0.1.1

修复用户实测中"删除后找不回"的三个根因，并补齐回收站支持。

### 修复

- **程序不再向源磁盘写入**：扫描结果存储位置与源盘相同时，结果只保留在内存中并在界面明确提示，可一键"保存结果到其它磁盘"；「设置 → 通用 → 结果存储位置」可改到另一块磁盘（WebView 缓存随之迁移）。扫描前弹出风险提示（存储位置 / 程序数据 / 程序本体是否在源盘上）。
- **回收站删除可按原路径找回（NTFS）**：解析已删除的 `$I` 记录，把 `$Recycle.Bin\<SID>\$Rxxxxxx` 条目还原为原始路径与真实删除时间；"指定目录找回"现在能命中经回收站删除的文件；结果页新增"经回收站删除"分组与标记。
- **TRIM / 已擦除数据明确标注**：对每个已删除文件探测首扇区，全零者标为"低·可能已被 TRIM 擦除"，并在结果页汇总警告，不再显示误导性的"高"。
- **FAT / exFAT 可恢复性评分错误**：分配位图索引与簇偏移不一致，导致被释放的簇被判为"已重新分配（低）"；已修正。
- **CLI `recover` 对带分区表的镜像写出错误数据**：extents 相对卷起始，现已按卷切片读取。
- NTFS：截断的非驻留属性不再触发越界 panic；空属性的 VCN 环绕不再溢出。
- "指定目录"模式按路径自动确定来源卷，不再要求手选磁盘。

### 验证

真实 NTFS / FAT32 / exFAT 卷（diskpart 生成，含回收站删除与 TRIM 两种情形）集成测试 8 项全部通过；CLI 在真实 NTFS 镜像上端到端恢复 6 个文件，SHA256 一致。详见 `docs/VALIDATION.md`。

### 重要提示

删除文件后请**立即停止向该磁盘写入**：不要在该磁盘上安装或运行本程序，不要把结果或恢复文件保存到该磁盘。系统盘（SSD + TRIM）上被删除的数据通常在数秒内被固件擦除，这不是软件能够挽回的。
